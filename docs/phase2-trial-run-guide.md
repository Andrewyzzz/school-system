## 1. 学部负责人手册

你能做什么：查看本学部人员档案（只读、敏感信息只见掩码）、发起本学部的入职/调岗/离职、处理属于本学部的审批步骤、查看本学部人事审计。

### 1.1 发起入职

1. 登录后进入「人事审批」→ 点「入职申请」。
2. 填写：姓名、电话、组织节点（只能选本学部）、岗位、任教学科（教师岗必填）、拟入职日期、发起原因。
3. 提交后流程进入「人事补全确认」，你可以在列表切到"全部流程"跟踪进度。
4. 终审通过后系统自动建档、开教师账号（工号小写为用户名，默认密码 123456，首次登录强制改密），你会在流程详情看到账号信息。

### 1.2 处理审批

- 「人事审批」页默认显示「我的待办」，右上角待办数变橙色表示有事项。
- 调岗流程中：原学部负责人处理"原学部确认"，目标学部负责人处理"目标学部确认"——不属于你的步骤不会出现在待办里。
- 拒绝必须填写原因；审批停留超过 3 个工作日系统会自动提醒。

### 1.3 发起调岗/离职

- 按员工工号发起；生效日期为必填。
- 发起后员工进入"调岗中/离职中"状态：调岗中原学部照常排课，离职中不能再被排入新课表。
- 离职终审通过后：生效日之后的已发布课程自动取消，教务会收到补位提醒；账号即时停用。

## 2. 人事专员手册

你能做什么：全校档案与组织架构维护、入职资料补全确认、档案变更申请审核、花名册导出、人事审计查询。看不到任何工资金额。

### 2.1 日常档案维护

- 「人员档案」：搜索/筛选/查看，编辑任何字段都必须填写修改原因。
- 证件号、银行卡：录入后系统加密存储，页面只显示掩码；确需查看完整值时点「查看完整」并填写原因，每次查看都会记入审计（含 IP）。
- 「导出花名册」只含掩码数据，每次导出留痕。

### 2.2 审批职责

- 入职流程第一步「人事补全确认」由你处理：核对姓名、证件、岗位、学科无误后通过。
- 老师本人提交的联系方式变更申请：在对应档案详情或「人事审批」处理。

### 2.3 组织与岗位

- 「组织与岗位」：维护架构树与岗位字典；停用节点前必须先处理该节点下全部非离职人员，系统会拦截并列出人数。
- 薪资模板的金额内容你不可见（显示"金额仅财务可见"），模板发布与批量应用由财务操作。

## 3. 总校管理员手册

你能做什么：全部流程终审、全校档案与审计查看、账号技术管理、风控停用。

### 3.1 终审

- 所有入职/调岗/离职的最后一步都在你的待办；终审通过即生效执行（建档/切换/离职），请确认生效日期与交接信息后再通过。
- 离职流程详情中的"交接清单"（生效日后课程数、未锁定工资数）供终审参考。

### 3.2 风控停用

- 人员档案 → 状态变更 → 「停用」：账号即时禁止登录、排课冻结、计薪冻结（工资生成会被拦截），档案保留在职；恢复选「在职」。
- 每次停用/恢复必须填写原因，全部留痕。

## 4. 老师（全员）说明

- 「我的档案」查看本人人事信息（证件只显示掩码）。
- 联系方式变了：在「我的档案」提交变更申请，人事审核通过后自动生效；待审核时可以撤回。

## 5. 试运行验收清单（学校 UAT 按此走一遍）

- [ ] 学部负责人发起一例真实入职 → 人事确认 → 总校终审 → 新账号登录成功且被要求改密。
- [ ] 发起一例跨学部调岗 → 双学部确认 → 终审 → 档案与教师学部同步切换，原学部收到课表移交提醒。
- [ ] 发起一例离职 → 终审 → 生效日后课程被取消、账号无法登录、离职当月工资固定项按天折算。
- [ ] 学部负责人尝试查看其他学部档案 → 被拒绝。
- [ ] 人事修改一名员工证件号 → 审计中可见掩码 diff；「查看完整」后审计出现敏感读取记录。
- [ ] 财务对停用人员生成工资 → 被拦截并提示冻结。
- [ ] `GET /api/phase1/readiness`：`hr_encryption_key`、`hr_timeout_scanner`、`hr_backfill`、`postgres_connection` 全部通过。

## 6. 常见问题

| 现象 | 原因与处理 |
| --- | --- |
| 保存档案提示"HR_ENCRYPTION_KEY 未配置" | 服务器缺少加密密钥环境变量，联系运维配置后重启；配置前系统拒绝写入敏感字段（不会明文保存） |
| 新入职老师排不进课 | 确认档案状态为试用期/在职，且行政已在任课配置中为其分配班级 |
| 离职人员仍出现在任课池 | 确认离职流程已终审生效（状态=已离职），生效前"离职中"仅冻结新增排课 |
| 审批待办不刷新 | 点击列表上方「刷新」，或重新进入页面 |
