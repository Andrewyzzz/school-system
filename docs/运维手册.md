# 运维手册

对应验收清单第六部分：6.1 部署手册、6.4 启停脚本、6.6 运维手册、6.8 迁移方案。

## 一、服务器规格（验收 6.1）

| 项目 | 最低 | 建议 | 说明 |
| --- | --- | --- | --- |
| CPU | 4 核 | 8 核 | 排课求解是 CPU 密集型，核数直接决定求解时间 |
| 内存 | 4 GB | 8 GB | 1000+ 教师全量加载约占 1.5 GB；求解器峰值另占 1–2 GB |
| 磁盘 | 50 GB | 100 GB SSD | 数据库约 2 GB/学年，备份保留 180 天另需约 15 GB |
| 操作系统 | Ubuntu 22.04 | Ubuntu 24.04 LTS | Debian 12 亦可 |
| 运行环境 | Node 22 | Node 22 LTS | 用到 `--env-file`，低于 20 不可用 |
| 数据库 | PostgreSQL 14 | PostgreSQL 16 | 用到生成列 + 可延迟外键 |
| Python | 3.10 | 3.11 | 仅排课求解器使用（OR-Tools） |

**端口规划**

| 端口 | 用途 | 对外 |
| --- | --- | --- |
| 443 | HTTPS，Nginx | 是 |
| 80 | HTTP → HTTPS 跳转 | 是 |
| 4173 | 应用，仅监听 127.0.0.1 | 否 |
| 5432 | PostgreSQL，仅监听 127.0.0.1 | 否 |

应用与数据库**都不应直接暴露在校园网上**。工资与身份证在明文 HTTP 上是可被抓包读取的。

## 二、部署（验收 6.2 / 6.3 / 6.7）

```bash
git clone <仓库> /tmp/school-system && cd /tmp/school-system
sudo bash deploy/install.sh
```

脚本覆盖：系统检查 → 依赖安装 → 账号与目录 → 代码部署 → 数据库初始化 → 配置生成 → 系统服务 → 启动自检。幂等，可重复执行；已有配置与数据不会被覆盖。

**执行完成后必须做的四件事**（脚本末尾会再提示一次）：

1. 配置 HTTPS：`certbot --nginx -d <域名>`，之后把 `FORCE_HTTPS` 改为 `1` 并重启
2. 轮换默认口令：`schoolctl` 所在目录执行 `node --env-file=config/production.env scripts/rotate-passwords.js --admins`
3. 验证备份可恢复：`schoolctl backup`
4. 抄下部署时打印的加密密钥，**与备份分开异地保管**

## 三、日常运维（验收 6.4 / 6.6）

```bash
schoolctl status      # 服务状态
schoolctl restart     # 重启
schoolctl logs 200    # 最近 200 行日志
schoolctl follow      # 实时日志
schoolctl health      # 健康检查
schoolctl backup      # 立即备份
schoolctl config      # 查看当前配置（密钥已打码）
schoolctl doctor      # 一键体检：服务 / 接口 / 数据库 / 权限 / 备份 / 口令
```

**每周例行**：跑一次 `schoolctl doctor`，重点看备份时间与权限体检两项。

**自动任务**

| 任务 | 时间 | 配置位置 |
| --- | --- | --- |
| 全量备份 | 每日 02:17 | `/etc/cron.d/school-system-backup` |
| 服务重启 | 每周日 03:40 | `school-system-restart.timer` |

两者刻意错开 80 分钟——备份进行到一半服务被重启，会留下一个有大小、却恢复不出来的 dump。

## 三之二、监控与告警（合同第七条第 6 项）

### 怎么看

系统管理员登录后进 `系统监控` 菜单。页面列出 10 项检查，异常的排在最前面。
点 `立即检查` 可以马上跑一轮，不用等下一个 5 分钟。

也可以直接调接口（需系统管理员令牌）：

```bash
curl -s -H "Authorization: Bearer <token>" http://127.0.0.1:4173/api/monitoring
```

### 检查了什么

| 检查项 | 级别 | 触发条件 | 处理方向 |
| --- | --- | --- | --- |
| 数据库连接 | 严重 | PostgreSQL 连不上 | 检查 postgresql 服务与网络 |
| 数据持久化 | 严重 | 最近一次保存失败 | **最危险的一类**：界面正常但改动只在内存，重启会丢 |
| 加密密钥 | 严重 | `HR_ENCRYPTION_KEY` 未配置 | 敏感字段会拒绝写入，补配置后重启 |
| 磁盘空间 | 严重 | 剩余 < 2 GB 或 < 5% | 清理旧备份或扩容 |
| 内存占用 | 警告 | 超过 `MONITOR_MEMORY_LIMIT_MB` | 归档往年账套，或重启服务 |
| 排课求解器 | 警告 | OR-Tools 不可用 | 排课会回退启发式，大年级排不满 |
| 数据备份 | 警告 | 超过 `MONITOR_BACKUP_MAX_DAYS` 没有新备份 | 检查备份定时任务 |
| 登录失败 | 警告 | 一小时内全站失败数超阈值 | 可能是口令爆破，查访问日志 |
| 三方对账 | 警告 | 当月对账未对平 | 在「账套管理」看差异台账 |
| 审批积压 | 提示 | 超 3 个工作日未处理的审批过多 | 提醒审批人 |

### 告警怎么发

三个通道同时发，互不牵连——任何一个失败都不影响其他的：

1. **日志**——`~/Library/Logs/school-system.log`（生产为 journalctl）。
   统一前缀 `[monitor]`，方便 grep：
   ```bash
   grep '\[monitor\]' /var/log/school-system.log | tail -50
   ```
2. **站内通知**——发给系统管理员，登录就能看到
3. **webhook**——可选，配 `MONITOR_WEBHOOK_URL` 接钉钉或企业微信

### 为什么不会被通知淹没

这是设计上刻意做的，运维要知道它的行为，否则会以为监控没在跑：

- **同一个故障只通知一次**。数据库断开的那一刻报一次，断开期间不再重复。
- **持续未恢复按 `MONITOR_REPEAT_HOURS`（默认 6 小时）重播一次**，
  防止凌晨发生的问题到早上被翻页翻没。
- **恢复后再通知一次**，所以看到「已恢复」才代表真的好了。
- **一个根因只发一条**。数据库断开时不会同时再报一条「持久化失败」。

所以「今天没收到监控通知」的正确解读是**没有新问题发生**，
不是「监控挂了」。想确认监控还活着，去 `系统监控` 页面看最近检查时间。

### 调整阈值

阈值都在环境变量里，改完重启服务生效。全部项见
`config/production.env.example` 的「监控与告警」一节。

告警太吵先调阈值，不要关掉整个监控——关掉之后没人会记得再打开。

## 四、异常排查（验收 6.6）

### 服务起不来

```bash
schoolctl logs 100
```

| 日志特征 | 原因 | 处理 |
| --- | --- | --- |
| `配置检查未通过` | 配置缺项或非法 | 按提示补 `config/production.env` |
| `EADDRINUSE` | 4173 被占用 | `ss -lptn 'sport = :4173'` 找到并处理 |
| `ECONNREFUSED ...5432` | 数据库没起来 | `systemctl status postgresql` |
| `password authentication failed` | 数据库口令不对 | 重跑 `scripts/provision-db-roles.js` 并同步更新配置 |
| 反复重启后停止 | 5 分钟内崩溃超 5 次触发熔断 | 先看日志定位根因，再 `systemctl reset-failed school-system` |

### 页面能开但功能报错

```bash
schoolctl health          # 后端是否正常
schoolctl doctor          # 数据库权限是否被改动过
journalctl -u school-system -p err -n 50
```

常见：恢复数据库后忘了重跑 `provision-db-roles.js`——`pg_restore` 会覆盖 GRANT，应用随即失去表权限。

### 工资金额显示异常或报解密失败

几乎必然是 `HR_ENCRYPTION_KEY` 与写入时不一致。**不要试图重新生成密钥**，那会让所有历史数据永久无法解密。找回原密钥后重启即可。

### 排课结果明显变差

```bash
schoolctl logs 50 | grep scheduler
```

出现「回退内置启发式算法」说明 OR-Tools 不可用（多半是 `SCHEDULER_PYTHON` 指错或虚拟环境被删）。系统不会因此报错，只会静默降级，所以要主动查。

### 故障隔离

| 影响面 | 措施 |
| --- | --- |
| 单个功能异常 | 记录复现步骤，不必停服 |
| 数据可能被写坏 | 立即 `schoolctl stop` + `schoolctl backup`（停服后再备份，避免备到中间状态） |
| 疑似越权或数据泄露 | 停服，保全 `db_audit_log` 与 journal 日志，再排查 |
| 数据库损坏 | 见第五节恢复流程 |

## 五、备份与恢复（验收 7.9–7.11）

```bash
schoolctl backup                                  # 立即备份（自动校验）
node scripts/backup-db.js --list                  # 列出所有备份
node scripts/backup-db.js --verify <文件>         # 单独校验某份备份
node --env-file=config/production.env scripts/restore-db.js            # 从最近一份恢复
node --env-file=config/production.env scripts/restore-db.js <文件> --force   # 覆盖现有库
```

恢复前脚本会自动把当前状态另存一份。**恢复后必须重跑** `scripts/provision-db-roles.js`——`pg_restore` 会覆盖数据库账号权限。

### 按时间点恢复（验收 7.11）

全量备份只能恢复到备份时刻。要恢复到任意时间点，需开启 WAL 归档：

```conf
# postgresql.conf
wal_level = replica
archive_mode = on
archive_command = 'test ! -f /var/backups/wal/%f && cp %p /var/backups/wal/%f'
```

恢复到指定时刻：

```bash
systemctl stop postgresql
# 用基础备份还原数据目录，然后：
cat > $PGDATA/recovery.signal <<'REC'
restore_command = 'cp /var/backups/wal/%f %p'
recovery_target_time = '2026-06-15 14:30:00+08'
REC
systemctl start postgresql
```

WAL 归档目录要与数据库放在**不同磁盘**，否则磁盘故障时基础备份与增量一起没。

## 六、服务器迁移（验收 6.8）

### 停机迁移（推荐，停机约 30 分钟）

```bash
# 旧机
schoolctl stop                     # 先停服，避免备到写了一半的状态
schoolctl backup
scp backups/<最新>.dump* config/production.env 新机:/tmp/

# 新机
sudo bash deploy/install.sh        # 会生成一份新配置
cp /tmp/production.env /opt/school-system/config/production.env   # 用旧配置覆盖
node --env-file=config/production.env scripts/restore-db.js /tmp/<最新>.dump --force
node --env-file=config/production.env scripts/provision-db-roles.js
schoolctl restart && schoolctl doctor
```

**关键一步是把旧的 `config/production.env` 带过去**。新机部署会生成一把新的 `HR_ENCRYPTION_KEY`，而数据是用旧密钥加密的——用新密钥启动，工资与人事字段全部解不开。恢复脚本会比对密钥指纹并拒绝执行，但前提是别用 `--ignore-key` 强行跳过。

### 迁移后核对

```bash
schoolctl doctor
# 逐项确认：教师数、班级数、课次数、工资单数与旧机一致
# 再以财务账号登录，打开任意一张工资单，确认金额能正常显示（验证密钥可用）
```

最后一步不能省：行数一致只证明数据搬过来了，证明不了它还能被读出来。

## 七、环境切换（验收 6.5）

```bash
node --env-file=config/production.env server/server.js   # 生产
node --env-file=config/test.env server/server.js         # 测试
```

模板见 `config/production.env.example` 与 `config/test.env.example`。

测试环境**必须**使用独立的数据库与独立的加密密钥。共用生产密钥意味着生产数据的加密强度被拉低到测试环境的管理水平——而测试环境往往权限更松、接触的人更多。
