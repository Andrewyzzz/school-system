# 账套操作手册

对应验收清单 9.8，同时作为第八章 18 项的现场演示脚本。
适用岗位：财务、教务、系统管理员、人事、校领导。

> 本手册按系统的实际界面编写，菜单名与按钮名与屏幕上完全一致。
> 界面改动后请同步修改本手册——`npm run test:manuals` 会检查手册里提到的
> 菜单与按钮是否还存在。

---

## 一、账套是什么

账套是**按期间分段存放的业务数据**。系统内置三套，互不混用：

| 账套 | 期间粒度 | 装什么 |
| --- | --- | --- |
| 人事账套 | 按年 | 该年度在册的教职工档案、合同、薪资记录 |
| 排课课时账套 | 按学期 | 该学期的课表、课次、课时确认 |
| 薪资财务账套 | 按月 | 该月的工资单与核算批次 |

三套各按各的期间切分：人事的 2026 年、排课的 2026-2027-1 学期、薪资的 2026-06，
彼此不会串。

### 四种状态

| 状态 | 能不能写 | 在不在内存 | 什么时候 |
| --- | --- | --- | --- |
| 使用中 | 能 | 在 | 建立后的默认状态 |
| 已锁定 | **不能** | 在 | 当期业务定案（例如工资审批通过） |
| 已归档 | 不能 | **不在** | 学年结束、数据不再变动 |

状态只能往前走：使用中 → 已锁定 → 已归档。**已归档是终态，不可逆。**

从"已锁定"回到"使用中"叫解锁，必须走三级审批（见第五节）——
界面上没有直接解锁的按钮。

### 归档为什么能加快系统

归档会把该期间的**期间数据**（课次、工资单、课表版本）从内存卸出。
五年的课次有三百多万条，全装进内存启动要两秒多、占七百多兆；
把往年归档之后，启动降到半秒、内存一百多兆。

**教师、班级、教室这类主数据不卸**——它们数量由学校规模封顶，不随年份增长，
而且到处要按 ID 查它们的名字，卸掉会让往年数据查出一堆没有名字的 ID。

归档**不影响查询**。往年的课表、工资单照样查得到、导得出，
只是查的时候从数据库现取，不常驻内存。

## 二、进入账套管理

侧边栏点 `账套管理`（菜单：账套管理）。

页面分四块：账套清单、新建账套、三方对账、审计报表导出。
系统管理员还会多一块"导入恢复"。

看得到不等于改得动：

| 岗位 | 看清单 | 建/锁/归档 | 导入恢复 | 导审计报表 |
| --- | --- | --- | --- | --- |
| 财务 | ✓ | ✓ | ✗ | ✗ |
| 教务 | ✓ | ✓ | ✗ | ✗ |
| 系统管理员 | ✓ | ✓ | ✓ | ✓ |
| 人事 | ✓ | ✗ | ✗ | ✓ |
| 学部负责人 | ✓ | ✗ | ✗ | ✓（限本学部） |
| 校领导 | ✓ | ✗ | ✗ | ✓ |

## 三、日常操作

### 3.1 新建账套

新学年或新核算月份开始时建立。在"新建账套"一段：

1. 选类型
2. 填期间——薪资填 `2026-09`，人事填 `2026`，排课填学期 ID（如 `2026-2027-1`）
3. 勾选"结转教职工名册"（默认勾选）
4. 点 `建立账套`

结转会把现有教职工名册带进新账套，并按在职、离职分列。
**新建账套不会清除任何往年数据**——往年工资、历史课表都还在。

期间已存在时不会重复建立，提示会写明。

### 3.2 看懂清单里的数字

清单表格有两组容易看混的数字：

- **本期明细**——归属这个期间的记录条数。人事账套按"该年度在册"统计，
  所以一个 2021 年入职、至今在职的老师，2021 到 2026 每一年的账套里都算他。
- **结转在职 / 结转离职**——结转时定格的名册快照。离职一列只统计**本期离职**的人，
  2023 年离职的人属于 2023 年的台账，不会逐年累积到之后每一年。

正常情况下，人事账套的"本期明细"应该等于"结转在职 + 结转离职"。

其余列：`可写`（对应能不能录数据）、`已加载`（归档后为"否"）、`解锁次数`。

### 3.3 结转名册

已建立的账套点 `结转名册` 可以重新结转一次。幂等——重复结转是覆盖同一份快照，
不会累加。

人员有变动（新入职、离职）后想让账套里的名册跟上，就重新结转一次。

### 3.4 锁定

当期业务定案后锁定。点 `锁定`，**必须填写原因**，这条会写进操作日志。

薪资账套在月度工资审批三级通过后会**自动锁定**，不需要手工点。

锁定之后：

- 该期间的工资不能再改、不能重新生成
- 清单里"可写"变成"否"
- 操作按钮里不再有"锁定"，只剩 `归档`、`申请解锁`、`导出备份`

### 3.5 归档

学期结束、数据不再变动后归档。点 `归档`，同样必须填原因。

排课账套在**学期结束后会自动锁定**，再过一段宽限期自动归档——
宽限期是留给补录考勤、处理遗留异常的。

归档后"已加载"列变成"否（归档）"。**归档不可逆**，没有取消归档的操作。

## 四、三方对账

**每月发工资之前必须跑一次。**

在"三方对账"一段选核算月份，点 `运行对账`。想看上次的结果点 `查看上次结果`。

系统核对三个口径：

| 口径 | 数据来源 |
| --- | --- |
| 人事在岗人数 | 人事档案 |
| 本月工资单数 | 薪资模块 |
| 排课总课时 vs 计薪课时 | 排课模块 vs 薪资模块 |

差异会落到**具体的人**（工号 + 姓名 + 原因），不是只给一个总数——
报"相差 4 人"等于把活儿推回给人工。

常见差异与处理：

| 差异 | 含义 | 怎么办 |
| --- | --- | --- |
| 在岗但无工资单 | 新入职漏建 | 补建工资明细 |
| 已离职，仍生成了工资单 | 离职流程没跟上 | 核实后作废该工资单 |
| 人事档案中无在岗记录 | 数据问题 | 联系人事核对档案 |
| 课时对不上 | 排课与计薪的课时数不一致 | 查考勤和调课记录 |

**对不平不要发钱。** 有差异时系统会推送通知；没有差异时不推——
每月推一条"一切正常"，人很快就学会忽略它了。

差异超过 200 条时列表只显示前 200 条，页面上会写明总共多少处。

## 五、申请解锁

已锁定的账套需要修改时，在清单里点 `申请解锁`。

系统会跳到 `审批中心` 并打开申请表，账套类型和期间已经填好，
需要补充：

- **解锁原因**——写清要改什么、为什么必须改
- **影响范围**——涉及多少人、多少金额

提交后走三级审批：财务复核 → 人事复核 → 校领导审批。
**三级全部通过后账套才会解开**，中间任何一级都不会提前解锁。

解锁会被记次数，显示在清单的"解锁次数"列。频繁解锁说明核算流程有问题，
正确的做法是锁定之前先把对账跑通。

在 `审批中心` 的"我发起的"页签可以跟进审批进度。

> **为什么没有直接解锁的按钮**：谁锁的谁就能解开，锁定就形同虚设。
> 而锁定的意义正是"这个月的账定案了，钱已经发出去了"。

## 六、备份与恢复

### 6.1 单账套备份

清单里点某个账套的 `导出备份`，下载一个 JSON 文件。

用途是把单个期间的数据交给档案室离线保存——例如"把 2025 学年的课表存档"。
这与整库备份分工不同：整库备份用于灾难恢复，只有整库备份的话，
想单独取一个学年的数据就得先恢复整个库。

### 6.2 导入恢复（限系统管理员）

在"导入恢复"一段选择备份文件，点 `导入恢复`。

默认**拒绝覆盖**已有数据。确需覆盖要先勾选"允许覆盖已有账套"，
系统会再确认一次——**覆盖不可撤销**。

导入时会核对文件里记录的每个集合条数。文件被截断会被拒绝——
只检查 JSON 能不能解析是不够的，截断在数组中间同样是合法 JSON。

### 6.3 换服务器时的整体迁移

单账套备份是逐个导的，换服务器不要用它。
用整库备份加恢复，具体步骤见 `docs/运维手册.md`。

## 七、审计报表导出

在"审计报表导出"一段选时间范围（留空表示全部），点 `导出审计报表`。

下载的是 Excel 文件，**脱离本系统也能打开**，可直接归档留存。四张表：

- **说明**——这份文件是什么、什么范围、谁导的、什么时候导的
- **人事审计**——谁改了谁的档案，改了哪个字段，前值后值，原因
- **系统审计**——谁做了什么系统操作
- **账套操作**——每个账套的建立、锁定、归档、解锁记录，含解锁审批单号

文件里的操作名、字段名都是中文。归档件是给几年后的人看的，
那时候可能连这套系统都不在了，键名等于没写。

学部负责人导出的内容按其可见范围裁剪——界面上看不到的记录，导出文件里也没有。

导出这个动作本身也会写进审计。

## 九、常见问题

**新建的人事账套"本期明细"是 0？**
检查一下这个年份是不是还没到。人事账套按"该年度在册"统计，
建 2027 年的账套时如果还没有人的入职日期落在 2027 年底之前，
那确实是 0。看"结转在职"列才是当前的人数。

**账套锁了，但我需要改这个月的工资。**
点 `申请解锁` 走三级审批。不要试图找直接解锁的按钮，没有。

**归档之后往年数据查不到了？**
查得到。归档只是不常驻内存，查询和导出都正常。如果确实查不到，
先确认查的月份或学期对不对。

**能删掉一个建错的账套吗？**
不能。系统不提供删除账套。建错了把它锁定并在原因里写明。

**导入恢复提示"已有数据"？**
默认拒绝覆盖。确认要覆盖再勾选"允许覆盖已有账套"。覆盖不可撤销，请先做整库备份。

**对账报出一千多处"在岗但无工资单"？**
这个月还没生成工资明细。先在 `薪资结算` 完成结算，再对账。

**审计报表导出很慢？**
全量导出会包含全部历史记录。按时间范围导出会快很多，例如只导本月。

## 十、注意事项

1. **归档不可逆**。归档之前确认这个期间的业务真的结束了。
2. **锁定之前先跑对账**。锁了要三级审批才能解。
3. **原因栏不是走过场**。锁定、归档、解锁的原因都会写进操作日志，
   是日后追溯的唯一线索。
4. **覆盖恢复前先做整库备份**。覆盖不可撤销。
5. **单账套备份不能代替整库备份**。换服务器要用整库备份。
6. **审计报表按机密资料管理**。里面是全校的操作记录。
