## 1. 项目背景与目标

### 1.1 产品定位

本系统是学校内部使用的管理平台，最终形态为「人事管控 + 排课 + 签入签出 + 工作量确认 + 薪资核算 + 审批风控」一体化系统。系统分三个阶段建设：第一阶段先打通任课老师的核心链路，确保在 2026 年 7 月中旬可支撑约 1000 个教师账号试运行；第二阶段补齐人员管控；第三阶段扩展到其他岗位薪资与 OA 流程。

第一阶段当前已经从单纯页面 Demo 升级为具备后端接口、角色权限、排课求解、动态二维码、签入签出、防作弊、工作量确认、两级审批、薪资生成、财务复核锁定、通知、审计、数据备份和自动化验收的可试运行版本。

### 1.2 三阶段总览

| 阶段 | 目标日期 | 核心目标 | 最终效果 |
| --- | --- | --- | --- |
| 第一阶段 | 2026-07-15 前 | 任课老师薪资明细、工作内容、排课系统可用 | 行政排课后老师可查看课表并签入签出，系统生成工作内容和薪资明细，老师确认、教务审批、总校审批后由财务复核锁定 |
| 第二阶段 | 2026-09-01 前 | 人员管控系统 | 入职、在职、调岗、离职、权限、岗位薪资模板可被系统控制，避免私自用人和无效人员计薪 |
| 第三阶段 | 2026-09 后迭代 | 其他人员薪资与 OA 扩展 | 行政、后勤、厨师、安保、招生等岗位进入统一薪资结算和审批体系 |

### 1.3 第一阶段目标

支撑约 1000 个教师账号使用，完成任课老师从排课到薪资明细的闭环：

> 行政排课 → 发布课表 → 老师查看本人课表 → 老师签入签出 → 系统生成工作内容 → 老师确认月度工作量 → 教务审批 → 总校审批 → 财务生成薪资明细 → 财务复核 → 财务锁定 → 导出工资明细。

### 1.4 业务价值

通过教室电脑动态短时二维码、后端签名、扫码时间窗口、本人课表校验、教室匹配、重复计薪拦截和异常不计薪，把「人是否真的来上了这节课」变成系统可校验的客观记录，使薪资明细可追溯、可复核、可锁定，降低人工统计课时的误差与争议，并为第二、三阶段的人员管控与全员薪资打好数据底座。

### 2.4 关键假设与依赖

- 课时类型与薪资单价需在正式试运行前由学校确认并冻结。
- 老师手机扫码场景需要在学校真实网络、真实手机、真实浏览器和微信环境中验证。
- 正式网页扫码必须使用 HTTPS；本地 `localhost` 仅用于开发验证。
- 教师、班级、科目、教室基础数据模板需要提前准备。
- 第一阶段保留手动调整、锁定重排和基础调课能力，避免只依赖自动排课。
- 薪资锁定后原则上不可修改；如需修改，必须走审批、留痕和重新生成规则。

## 3. 用户角色与权限

第一阶段定义四个角色：`teacher` / `admin` / `finance` / `system_admin`。试运行期由 `admin` 账号承担教务排课、工作量审批、教师账号导入、重置、停用等管理动作；`finance` 负责薪资规则、薪资生成、复核、锁定和导出；`system_admin` 为系统预留最高管理角色。

### 3.1 角色职责

| 角色 | 账号示例 | 职责 | 当前状态 |
| --- | --- | --- | --- |
| 老师 teacher | `teacher0001` 至 `teacher1000`、`teacher` | 查看本人课表、今日任务、签入签出、考勤记录、月度工作内容、月度确认、本人薪资明细 | 已完成 |
| 行政/教务 admin | `admin` | 基础数据与任课关系配置、一键排课、冲突校验、手动调整、锁定/重排、发布课表、调课审批、教师导入、重置密码、启用/停用账号、工作量教务/总校审批 | 已完成 |
| 财务 finance | `finance` | 分页查看教师列表、单人工作内容与异常、薪资规则配置、月度薪资试算、批量生成、复核、锁定、导出 | 已完成 |
| 系统管理员 system_admin | 预留 | 系统级配置、跨角色管理、最高权限 | 接口已预留，前端第一阶段不重点展开 |

### 3.2 权限矩阵（数据访问边界）

| 数据/能力 | 老师 | 行政 | 财务 | 系统管理员 |
| --- | --- | --- | --- | --- |
| 本人课表/考勤/工作量/薪资 | 仅本人 | 全部（审批/排课相关） | 全部（核算相关） | 全部 |
| 他人课表/考勤/工作量 | 不可访问 | 可查看和审批 | 可查看和核算 | 全部 |
| 基础数据与任课关系配置 | 不可操作 | 可操作 | 不可操作 | 可操作 |
| 一键排课/调整/发布 | 不可操作 | 可操作 | 不可操作 | 可操作 |
| 工作量审批 | 老师本人确认 | 教务审批、总校审批 | 不可审批 | 可审批 |
| 薪资规则/生成/复核/锁定/导出 | 仅查看本人明细 | 不可复核锁定 | 可操作 | 可操作 |
| 教师导入/重置密码/停用账号 | 不可操作 | 可操作 | 不可操作 | 可操作 |
| 通知查看 | 本人/老师通知 | 行政通知 | 财务通知 | 全部或系统通知 |

> 权限要点：老师本人数据访问限制由后端角色权限强制执行，任何接口都不得让老师越权访问他人数据。

## 4. 核心业务流程

### 4.1 主链路（端到端）

```text
行政配置基础数据与任课关系
        |
        v
行政一键排课 -> 冲突校验(老师/班级/教室/硬约束/全局占用) -> 手动调整 / 锁定 + 重排未锁定
        |
        v
行政确认发布课表（生成老师端课次任务并通知老师）
        |
        v
老师端按自然周看到本人课表与今日任务
        |
        v
上课前扫码签入 -> 下课后扫码签出（本人+教室+动态码+时间窗口+幂等校验）
        |
        v
系统自动生成工作内容（按课时类型计课时）
        |
        v
月末老师确认月度工作量
        |
        v
教务审批 -> 总校审批
        |
        v
财务按薪资规则生成薪资明细（单人/批量）
        |
        v
财务复核 -> 财务锁定 -> 导出工资明细 CSV
```

### 4.2 状态流转

| 对象 | 状态流转 | 当前状态 |
| --- | --- | --- |
| 课次 `lessonInstances.status` | `scheduled` → `checkedIn` → `completed`；异常为 `exception` | 已实现 |
| 考勤 `attendanceRecords.status` | `accepted` / `rejected` / `exception` | 已实现 |
| 工作量确认 `workloadConfirmations.status` | `teacher_confirmed` → `academic_approved` → `school_approved` → `locked` | 已实现，已超出 v1.0 |
| 薪资明细 `payrollDetails.status` | `generated` → `reviewed` → `locked` | 已实现 |
| 调课申请 `scheduleChangeRequests.status` | `pending` → `approved` | 基础版已实现，驳回/撤回后续补 |

### 4.3 薪资锁定前置条件

财务锁定单个老师工资前，系统必须同时满足：

1. 老师已确认月度工作量。
2. 教务已审批。
3. 总校已审批。
4. 财务已复核。
5. 不存在待处理课时。
6. 不存在异常课时。
7. 当前月薪资尚未锁定。

## 5. 功能需求详述

### 5.1 账号与权限 / 管理后台（ACC）

| 编号 | 功能 | 说明 | 验收标准 | 当前状态 |
| --- | --- | --- | --- | --- |
| ACC-01 | 登录 | 账号密码登录，返回 Token；前端优先连后端，后端不可用时保留本地 Demo 登录兜底 | 1000 个教师账号 + 行政 + 财务均可登录 | 已完成 |
| ACC-02 | 当前账号信息 | 返回当前登录账号角色、姓名、部门、状态 | 登录后可读取本账号信息与角色 | 已完成 |
| ACC-03 | 修改密码 | 当前账号自助修改密码 | 修改后旧密码失效、新密码可登录 | 已完成 |
| ACC-04 | 密码加密存储 | 密码以 `passwordHash` 加密存储，不明文落库 | 数据存储中无明文密码 | 已完成 |
| ACC-05 | 角色权限中间件 | 按角色限制接口访问；老师仅本人数据 | 老师越权访问他人数据被拒绝 | 已完成 |
| ACC-06 | 教师批量导入（预览） | 行政粘贴 CSV，后端校验并规范化，不写库 | 错误行可定位并展示原因 | 已完成 |
| ACC-07 | 教师批量导入（确认） | 重新执行完整校验后写入教师档案与账号，记录导入审计日志 | 通过记录生成教师+账号；重复工号/用户名被拦截 | 已完成 |
| ACC-08 | 重置密码 | 行政重置指定账号密码 | 重置后默认密码可登录，旧会话撤销 | 已完成 |
| ACC-09 | 启用/停用账号 | 行政停用或启用账号 | 停用账号无法登录，旧会话撤销 | 已完成 |
| ACC-10 | 角色体系 | 支持老师、行政、财务、系统管理员四角色 | 各角色仅见各自允许的功能 | 已完成 |
| ACC-11 | 持久会话 | 登录态写入后端会话表，服务重启后可按会话恢复 | Token 不明文保存，过期或撤销后不可用 | 已完成，超额 |
| ACC-12 | Token 哈希存储 | 仅保存 token hash | 数据文件不出现可直接使用的明文 token | 已完成，超额 |

导入校验规则：`employeeNo`、`username` 必填且系统内唯一；`stageId` 必须为 `primary/middle/high`；`primarySubjectId` 必须为系统支持科目；`status` 留空默认 `active`；`defaultPassword` 留空默认 `123456`；同一份文件内部不得出现重复 `employeeNo` 或 `username`。

## 7. 接口清单（第一阶段当前实现）

### 7.1 账号与认证

- `POST /api/auth/login` 登录返回 Token。
- `POST /api/auth/logout` 注销并撤销会话。
- `GET /api/me` 当前账号。
- `POST /api/auth/change-password` 修改密码。

### 7.2 通知

## 8. 非功能需求

### 8.1 性能与规模

- 支持约 1000 个教师账号。
- 教师列表、薪资列表必须分页。
- 财务端按月份查询，避免跨年全量扫描。
- 排课求解应输出求解状态、冲突数量、未排数量、目标值和耗时。
- 当前本地 JSON 模式可支撑试运行演示；正式数据库迁移后必须建立索引。
- 批量薪资当前为同步接口，若正式生产遇到超时，应升级为后台任务队列。

### 8.2 安全

- 密码加密存储。
- Token 不明文落库，只保存 hash。
- 后端持久会话支持过期、撤销和最近访问时间。
- 修改密码、重置密码、停用账号会撤销相关会话。
- 老师仅能访问本人数据。
- 教室大屏密钥不得写入公开文档或贴在教室外部。
- 老师默认密码上线前应强制修改。当前有 `mustChangePassword` 字段，正式上线前需要增加前端强制改密拦截。

### 8.3 幂等与可追溯

- 签到接口必须幂等，重复请求不产生重复有效计薪。
- 排课发布生成可追溯发布课次。
- 调课审批写入申请和审批记录。
- 工作量确认、教务审批、总校审批、财务复核、财务锁定均需留痕。
- 关键操作写入 `auditLogs`。
- 财务锁定后不可重复生成或绕过审批修改。

### 8.4 扫码与兼容性

- 正式网页摄像头扫码需要 HTTPS 安全上下文与用户授权。
- 本地 `localhost` 可用于开发验证。
- 权限失败时保留手动输入二维码内容兜底。
- 后续微信小程序版本改用微信原生扫码入口，复用同一套后端考勤接口。
- 需在学校实际手机、浏览器、网络环境中验证扫码兼容性。

### 8.5 数据存储与备份

- 当前阶段使用本地 JSON 数据文件。
- 每次保存前自动备份旧数据文件。
- 备份目录为 `server/data/backups`。
- 最多保留 50 份备份。
- 正式上线前建议按 `docs/database-migration-plan.md` 迁移到 PostgreSQL/MySQL。

## 9. 防作弊与异常规则（汇总）

| 场景 | 系统处理 | 是否计薪 |
| --- | --- | --- |
| 本人课程 + 指定教室 + 有效时间窗口内有效签入并签出 | 形成有效工作内容 | 是 |
| 非本人课程扫码 | 拦截并记录异常尝试 | 否 |
| 非指定教室扫码 | 拦截并记录异常尝试 | 否 |
| 非有效时间窗口扫码 | 拒绝或标记异常 | 否 |
| 动态二维码过期 | 拒绝 | 否 |
| 动态二维码签名不匹配 | 拒绝 | 否 |
| 重复扫码（同一节课重复签入或签出） | 拦截，不重复计薪 | 不重复计薪 |
| 只签入未签出 | 超过签出窗口后自动标记异常 | 否 |
| 未签入直接签出 | 拒绝 | 否 |
| 存在待处理或异常课时 | 财务锁定被阻止 | 处理后再核算 |

## 10. 验收标准

### 10.1 验收口径

- 老师账号 `teacher0001` 至 `teacher1000` 可登录。
- 老师账号只能查看本人课表、考勤、工作量与薪资。
- 财务和行政可分页查看教师列表。
- 行政可生成老师、班级、教室无冲突课表。
- 行政发布后老师端能看到本人自然周课表。
- 教室电脑可展示实时动态二维码。
- 老师端支持摄像头扫码和手动输入兜底。
- 签入签出具备时间窗口、教室、老师、动态码签名、动态码有效期和重复扫码校验。
- 异常扫码和未完成签出不计入薪资。
- 老师可确认月度工作量。
- 行政可完成教务审批和总校审批。
- 财务可批量生成、复核、锁定单个老师月度薪资并导出 CSV。
- 通知中心可读取后端通知并标记已读。
- 试运行操作手册、已知问题清单、上线验收清单完成。

### 10.2 自动验收

财务或行政登录后调用：

```text
GET /api/phase1/readiness
```

返回账号数量、权限、分页性能、排课发布、扫码考勤、异常不计薪与薪资锁定等自动检查结果。

当前新增代码级验收脚本：

```text
node tests/phase1-production.test.js
```

覆盖：

- 1000 老师账号数据。
- 排课生成和发布。
- 持久会话创建、读取、撤销。
- 后端通知创建、定向读取、已读。
- 未审批前禁止财务复核。
- 老师确认、教务审批、总校审批。
- 薪资生成、复核、锁定。
- 第一阶段 readiness 检查。
