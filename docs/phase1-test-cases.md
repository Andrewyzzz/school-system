# 第一阶段详细测试案例

更新时间：2026-06-18  
适用范围：第一阶段任课教师链路，包括账号权限、行政排课、教室动态二维码、老师签入签出、月度工作量确认、专任教师工资计算、财务复核锁定、工资导出和手机端适配。

## 3. 测试前准备

1. 确认服务可访问：

```bash
curl http://127.0.0.1:4184/api/health
```

期望返回：

```json
{
  "status": "ok",
  "service": "school-system-phase1-api"
}
```

2. 自动化检查通过：

```bash
node --check app.js
node --check server/payroll.js
node --check server/storage.js
node --check server/server.js
node --check server/importTeachers.js
node tests/phase1-production.test.js
git diff --check
```

3. 手机扫码测试必须使用 HTTPS 正式测试站，或确认浏览器允许 `localhost` 的摄像头权限。普通 HTTP 局域网地址通常不能调用手机摄像头。

4. 每轮正式验收前，测试人员应明确是否允许重置测试数据。若已经进入学校真实试运行，不允许随意点“重置数据”。

## 9. 验收通过标准

第一阶段建议按以下标准判定：

| 类别 | 标准 |
| --- | --- |
| P0 | 全部通过，任何 P0 不通过都不建议试运行 |
| P1 | 与工资、权限、签到防作弊相关的 P1 必须通过；体验类 P1 可评估后修复 |
| P2 | 不阻塞试运行，但应进入上线前优化清单 |
| 自动化测试 | `tests/phase1-production.test.js` 必须通过 |
| 手机扫码 | 至少 iPhone Safari、微信内置浏览器、Android Chrome 各测 1 台 |
| 数据一致性 | 行政发布课表、老师看到课表、扫码完成课次、财务工资明细四者必须一致 |
| 薪资口径 | 第一阶段只按实际完成课次计薪，不按排班理论课次或 `4.4` 自动折算课次 |
