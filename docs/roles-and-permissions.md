# 角色与权限说明

更新时间：2026-07-08
适用版本：第二阶段交付版
原则：**一个角色一条主职责线**，跨线操作走流程（审批/申请），不靠开权限解决。

## 1. 角色总览（7 个）

| 角色 | 账号示例 | 一句话职责 | 默认首页 |
| --- | --- | --- | --- |
| 老师 `teacher` | teacher0001 | 上课的人：看自己的课表与课时、发起调课/请假申请、确认自己的工资、管理自己的账户 | 工作台 |
| 教研所 `admin` | admin | 排课的人：课程规则、任课配置、排课发布、调课 | 行政排课 |
| 财务 `finance` | finance | 管钱的人：薪资规则与模板金额、工资生成/复核/锁定/导出 | 财务首页 |
| 人事专员 `hr` | hr | 管档案的人：组织架构、全员档案、合同、入职资料确认、变更审核（**看不到任何工资金额**） | 人员档案 |
| 学部负责人 `division_head` | head_primary | 本学部的人事发起与确认：发起入职/调岗/离职、处理本学部审批步骤、只读本学部档案 | 人事审批 |
| 行政管理 `system_admin` | sysadmin | 兜底与终审的人：全部人事流程终审、账号技术管理（重置密码/停用）、教师导入、全局查看 | 人员列表 |

## 3. 本次收敛决策（2026-07-08）

1. **「人员列表」从 教务+行政管理 收归 行政管理独有**。理由：该页的实际操作（重置密码、启停账号）本来就只有行政管理能执行，教务打开只能看不能动，属于权限噪音；教务的人员信息需求由排课页的任课配置覆盖。
2. **「行政管理」不单设角色，由 system_admin 承担**（PRD 原文即如此）。终审 + 技术管理合一，避免再多一个要维护的账号层级；如学校日后要求"技术运维不碰业务终审"，再拆分。
3. **老师端「总薪资」并入「工资确认」**：原总薪资页只是摘要+跳转按钮，与月度确认的金额条重复，已合并为单页。
4. **「我的档案」从导航栏目改为账户中心**：点击左下角账户卡进入，减少一个导航项。

## 3.1 数据归属原则（2026-08-07 修正）

**人事管事实、财务管金额**：

| 类别 | 归属 | 理由 |
| --- | --- | --- |
| 职称、学历 | 人事 | 是评定结果与证书事实。若由财务维护，改一下职称就等于直接改基本工资档，职责分离失效 |
| 兼岗任命（班主任、年级主任、教研组长等） | 人事 | 是"担任什么职务"的任命，不是薪资参数 |
| 月度考核结果 | 学部负责人 / 人事 | 是线下评审结论。财务不掌握教师日常表现，不应决定考核等级 |
| 校龄、试用期折算 | 系统自动推导 | 分别由入职日期与人事状态得出，不再手工维护，避免与人事档案不一致 |
| 薪资标准金额、考核档位、住房档、月度奖扣 | 财务 | 这些才是"钱的标准" |

财务侧工资档案页以只读区展示上述人事事实及其对应金额，使财务看得到计算依据但改不了依据本身。

## 4. 明确不合并的组合（及原因）

| 组合 | 不合并原因 |
| --- | --- |
| hr + finance | **职责分离红线**：管档案的人不能看工资金额（PRD 权限矩阵），合并即失去制衡 |
| admin + hr | 排课与人事是两条业务线；人事状态通过联动矩阵自动影响排课，不需要同一个人操作 |
| admin + system_admin | 教务是高频业务角色，行政管理是低频管理角色；合并会让日常排课账号拥有全校终审与账号管理权，风险外溢 |
| division_head + hr | 学部负责人是"申请方+本学部确认方"，人事是"全校执行方"；合并后审批链退化为自审自批 |

## 5. system_admin 出现在多数接口角色列表里的说明

这是**兜底代理**设计而非权限混乱：任何审批步骤的处理方缺位（学部负责人离职、人事请假）时，行政管理可代理处理，全部操作照常留痕。日常使用中 system_admin 不应参与常规操作，只做终审与异常兜底。
