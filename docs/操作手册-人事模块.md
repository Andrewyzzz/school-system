# 人事模块操作手册

对应验收清单 9.1。适用岗位：人事专员、学部负责人、系统管理员。

> 本手册按系统的实际界面编写，菜单名与按钮名与屏幕上完全一致。
> 界面改动后请同步修改本手册——`npm run test:manuals` 会检查手册里提到的
> 菜单与按钮是否还存在。

---

## 一、开始之前

### 谁能做什么

| 岗位 | 能看 | 能改 |
| --- | --- | --- |
| 人事专员（hr） | 全校人事档案、组织架构、人事审批、人事审计 | 建档、改档、变更状态、组织架构、薪资模板 |
| 学部负责人（division_head） | **本学部**人事档案与审批 | 本学部范围内的档案 |
| 系统管理员（system_admin） | 全部 | 全部，含账号启停与重置密码 |
| 财务（finance） | 组织与岗位（看岗位薪资模板） | 不能看人事档案 |

财务看不到人事档案是有意为之：工资金额与身份证号分属两个岗位，一个人同时拿到
两样，出了事查不清是谁泄的。

### 登录

浏览器打开学校发的地址，用工号和密码登录。首次登录后请立即修改密码。

## 二、人员档案（菜单：人员档案）

这是人事模块的主界面，全校教职工档案都在这里。

### 2.1 查人

顶部工具条填姓名、工号或手机号，点 `查询`。学部、状态、岗位可以叠加筛选。
结果按页显示，用 `上一页` / `下一页` 翻页。

点某一行进入档案详情，里面分几段：基本信息、人事状态、合同、薪资档案、证件附件、变更历史。

身份证号和银行卡号默认打码显示。需要看完整号码时点 `查看完整`，
**这一次查看会记进人事审计**，包括是谁、什么时候、看了谁的哪个字段。

### 2.2 新建档案

点右上角 `新建档案`，填写：

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| 姓名 | 是 | |
| 工号 | 是 | 全校唯一，重复会被拒绝 |
| 入职日期 | 是 | 决定这个人属于哪一年的人事账套 |
| 学部 / 组织单元 | 是 | 决定学部负责人能否看到 |
| 身份证号 | 否 | 存入时自动加密 |
| 手机号 | 否 | |
| 建档原因 | **是** | 会写进审计日志 |

填好点 `创建档案`。想放弃就点 `取消`。

> **建档原因为什么必填**：半年后翻审计日志，"新建了一条档案"说明不了任何事；
> "2026 秋季入职批次"能让人立刻想起当时在做什么。

### 2.3 修改档案

在档案详情里改字段，点 `保存档案`。修改原因同样必填。

系统只记录**真正变化的字段**，前值后值都留档。什么都没改就保存会被拒绝，
不会产生一条空的审计记录。

### 2.4 变更人事状态

档案详情的"人事状态"一段，选新状态，填变更原因，点 `变更状态`。

可选状态：待入职、试用期、在职、调岗中、离职中、已离职、停用。

**离职和停用会同步冻结这个人在教学侧的账号资格**——他登不上系统，也不会再被
排进新课表。已经排好的课不会自动取消，需要教务去调课。

> 系统**不物理删除**员工档案，离职只是改状态。已经发过的工资单、上过的课都指向
> 这条档案，删掉会让往年的账对不上。

### 2.5 证件附件

档案详情下方可以上传身份证、学历证、职称证的扫描件。

- 支持 JPG、PNG、PDF，单个文件不超过 10 MB
- 文件内容**加密后**存盘，直接翻服务器目录看不到内容
- 下载时系统会校验文件指纹，被改动过的文件拒绝下载

### 2.6 导出花名册

点 `导出花名册` 下载 Excel。导出的是当前筛选条件下的结果，不是全校。

导出动作本身会记审计（`roster_export`）——花名册是全校人员的联系方式，
谁导过必须留痕。

## 三、组织与岗位（菜单：组织与岗位）

### 3.1 组织架构

左侧是学校的组织树。点 `新增节点` 加部门，选中节点点 `改名` 改名称。

删除节点：节点下还有人时不允许删除，要先把人调走。

### 3.2 岗位与薪资模板

右侧是岗位薪资模板。一个模板定义一类岗位的工资构成（基本工资、岗位工资、
考核工资等）。

改模板的流程是**发版**而不是直接改：

1. 修改模板内容
2. 点 `发布新版本`——旧版本保留，历史工资单仍按旧版本解释
3. 点 `批量应用` 把新版本套到符合条件的人身上

> 为什么要发版：直接改模板会让三个月前的工资单"重新计算"出不同的数字，
> 而那笔钱已经发出去了。

---

## 四、人事审批（菜单：人事审批）

入职、调岗、离职三类流程在这里流转。

页面列出待办的人事流程，点 `刷新` 拉取最新。点某一条看详情，
按流程节点逐级审批。

普通的请假、加班、补卡等日常审批不在这里，在 `审批中心`（见第六节）。

---

## 五、人事审计（菜单：人事审计）

人事域的全部操作都在这里留痕，**只能追加，不能修改和删除**——
数据库层面也做了限制，改一条审计记录会被数据库直接拒绝。

每条记录包含：谁、什么时候、对谁、改了哪个字段、前值、后值、为什么。
敏感字段（身份证、银行卡）只记掩码，不记明文。

用顶部的操作类型下拉和搜索框筛选，点 `查询`。

### 常用查法

| 想查什么 | 怎么查 |
| --- | --- |
| 某个人的档案被谁改过 | 搜索框填这个人的姓名或工号 |
| 谁看过身份证号 | 操作类型选"查看敏感字段" |
| 谁导出过花名册 | 操作类型选"导出花名册" |
| 某天发生了什么 | 按时间倒序翻页 |

---

## 六、审批中心（菜单：审批中心）

全校通用的审批入口，人事岗在这里处理和发起审批单。

四个页签：

- `待我审批`——轮到我的
- `我发起的`——我提交的，看进度
- `我处理过`——历史记录
- `抄送我的`——不需要我审批，但需要我知道

点 `刷新` 拉取最新。点某一条打开详情，可以同意、驳回，或添加抄送人。

---

## 七、账号管理（菜单：人员列表，限系统管理员）

人事档案管的是"人"，账号管的是"能不能登录"。两者通过工号关联。

在 `人员列表` 里可以 `重置密码` 和 `停用账号`。

停用账号 ≠ 离职。离职要在 `人员档案` 里变更人事状态，那才会同步冻结教学资格。

## 八、常见问题

**改了姓名，排课那边还是旧的？**
不会。教学侧读的就是人事档案，人事一改，排课、工资立刻就是新的，不需要任何同步操作。
如果确实没变，先刷新页面；仍不变请联系管理员。

**新建档案提示工号已存在？**
工号全校唯一。先在 `人员档案` 里搜这个工号，可能这个人已离职但档案还在——
离职档案默认不在"在职"筛选里，把状态筛选改成全部再搜。

**能删掉一条建错的档案吗？**
不能。系统不提供物理删除。建错了把状态改成"停用"并在原因里写明。
这是为了保证已发工资、历史课表能一直追溯到人。

**上传证件提示格式不支持？**
只认 JPG、PNG、PDF。系统按文件内容判断格式，把 .txt 改名成 .jpg 也过不了。

**审计里看到自己不认识的操作？**
先看操作人是谁。如果是"系统"，那是自动流程（例如账套结转）触发的。
如果是某个同事而你认为他不该有这个权限，联系系统管理员核对角色配置。

---

## 九、注意事项

1. **原因栏不是走过场**。所有改动都要填原因，它是日后追溯的唯一线索。
2. **不要共用账号**。审计记到账号，共用等于查不出是谁做的。
3. **导出的花名册按内部资料管理**。里面有全校教职工的联系方式。
4. **发现数据错了不要绕过系统改库**。直接改数据库不会留审计，也不会触发联动。
