# 学校测试环境部署交接清单

适用版本：`uat-2026-09-11`

## 一、学校需提前准备

- 一台独立测试服务器：Ubuntu 22.04/24.04 或 Debian 12，建议 4 核 CPU、8GB 内存、100GB SSD。
- 一个校园网内可访问的测试域名，以及对应 HTTPS 证书。测试人员通过校园网或 VPN 访问。
- 网络规则：只向测试人员开放 443；22 仅允许学校 IT 与我方维护来源；4173、5432 只允许服务器本机访问。
- 一个可 SSH 登录并具有必要 `sudo` 权限的 Linux 管理账号，或由学校 IT 全程现场执行命令。
- 一个与应用服务器分离的备份位置，例如 NAS、另一块磁盘或校内备份服务器。
- 一名现场 IT 联系人、可用的测试时间窗，以及小学部排课、人员、财务三类业务确认人。

上述项目中，服务器、管理权限和可访问方式是部署当天的必需项；域名与正式证书可由学校 IT 在限定测试人员范围内先行配置，但测试涉及人员与工资数据，不应长期使用明文 HTTP。

## 二、我方交付

- GitHub 代码标签：`uat-2026-09-11`。
- 与 GitHub 分离的加密数据迁移包：数据库、附件、清单、校验值。
- 迁移包口令通过另一通道交付，不与迁移包放在一起。
- 部署脚本、运维手册、测试账号交接表与现场演示流程。

GitHub 仓库不包含真实名册、工资数据、手机号、账号口令或本地数据库。

## 三、部署当天顺序

1. 学校 IT 确认服务器、时间同步、磁盘和网络策略。
2. 检出 `uat-2026-09-11`，执行 `deploy/install.sh`。
3. 停止应用，解密数据迁移包，恢复 PostgreSQL 与附件。
4. 重新配置数据库最小权限，启动服务。
5. 配置 Nginx 与 HTTPS，确认 4173、5432 未对校园网开放。
6. 运行健康检查与备份恢复检查。
7. 小学部负责人演示：人员与任课关系 → 预检 → 生成草稿 → 人工检查；测试环境首次演示不直接发布全校课表。
8. 财务、人事、校长、学部主任、教师各抽取一个账号核对权限边界。
9. 学校 IT 接收加密密钥与备份口令，并与数据库备份分开保管。

## 四、部署后必须通过

- 健康检查状态为 `ok`，数据层为 `postgres`，PostgreSQL 已连接。
- 排课求解器显示 `ortools-cp-sat`。
- 真实教师、校长、财务主任、学部主任和小学任课关系数量与迁移清单一致。
- 小学部排课预检无阻断项；周日固定日程进入老师端但不参与自动排课。
- 跨年级、跨 A/B/C 班教师的时间冲突会被拦截。
- 学部财务只能查看和核算本学部；只有授权总校财务可导出全校工资。
- 当场创建一次备份并校验可恢复，附件也包含在备份清单中。

## 五、回滚原则

部署或数据核对未通过时，先停止服务并保留日志，不在问题未定位时反复导入。代码回到上一个已知可用标签；数据使用部署前自动备份恢复。任何覆盖恢复必须由学校 IT 与我方共同确认目标数据库名称。
