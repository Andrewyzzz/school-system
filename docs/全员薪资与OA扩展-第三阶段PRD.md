## 1. 阶段定位与总体策略

第三阶段把系统从「任课教师薪资 + 人事管控」扩展为**全员薪资、全员考勤、基础 OA** 的统一平台。

生产运营的核心策略是**分批上线、每批可独立验收回滚**，不做一次性大爆炸发布：

| 批次 | 主题 | 目标窗口 | 独立价值 |
| --- | --- | --- | --- |
| 3A | 全员移动考勤 | 2026-09 | 非教学岗位有客观出勤记录 |
| 3B | 各岗位工资方案引擎 | 2026-09 → 10 | 全员工资进系统结算 |
| 3C | 请假/加班/调课 OA 审批 | 2026-10 → 11 | 考勤异常有制度化出口 |
| 3D | 考勤扣款与薪资联动 | 2026-11 → 12 | 迟到早退旷工自动进工资 |
| 3E | 津贴评审、报销与全员报表 | 2026-12 → 2027-01 | 名师津贴/课题奖励/寒暑假工资闭环，总校看全貌 |

排序依据：先有考勤数据（3A），才能算非课时工资（3B）；先有请假加班审批（3C），才能公平地做扣款（3D）；评审与报表最后收口（3E）。

## 2. 批次范围详述

### 3A 全员移动考勤（ATT2）

范围：行政干部、司机、校医、生活老师、食堂、幼儿园、招生、安保等非课时岗位的上下班打卡。

- ATT2-1 打卡方式：手机网页/小程序打卡，校验方式二选一由学校确认——① 校园 Wi-Fi/IP 段校验；② 定位围栏（需明确告知并取得员工同意，合规提示见 8.2）。教师课时签到仍走一阶段教室动态码，不混用。
- ATT2-2 班次模型：固定班次（如 8:00-17:30）、轮班（司机/安保排班表）、弹性（行政干部仅记录）；班次由学部负责人维护。
- ATT2-3 原始记录不可改：打卡流水只增不改，纠错走补卡申请（3C 审批）。
- ATT2-4 异常标记：迟到、早退、缺卡、旷工按班次规则自动标记，仅记录不扣款（扣款在 3D）。
- ATT2-5 值班/跟车/晚托等特殊工时：生活老师、司机的多维工作量先按「工时事件」录入（学部负责人录入+员工确认），为 3B 计薪提供数据。

明确不做：人脸识别、硬件闸机对接（有需求再立项）。

### 3B 各岗位工资方案引擎（PAY2）

把一阶段"专任教师工资方案结构化"的做法推广到全部岗位。每个方案 = 固定项 + 变动项 + 系数/阶梯规则，全部版本化。

| 岗位 | 方案要点（源自学校制度文件） |
| --- | --- |
| 行政干部 | **部门 × 类别 × 职级三维工资表**（约 69 格，每格含基本/岗位/职级/考核四项）、兼课课时（复用一阶段课时计算）、住房补贴、寒暑假工资资格；兼任两职**就高不就低**，无额外兼岗工资 |
| 教辅职员 | **5 级职员 × 5 档工资表**（25 格，每格四项）、兼岗津贴（工资核算员/财产管理员/电教技术/实验员/心理健康中心）、住房补贴 1500 |
| 司机 | A/B 牌岗位工资档、车队长津贴、通讯补贴、校龄、住房补贴、跟车/加班工时（来自 3A 工时事件） |
| 校医 | 医生/助理/护士岗位档、主管/副主管津贴、校龄、住房补贴 |
| 生活老师 | 楼栋/年级/班级/宿舍/跟车/晚托多维工作量计薪（工时事件 × 单价） |
| 食堂 | 岗位工资、绩效、周末/日常/夜宵加班（3A 数据）、寒暑假工作补贴 |
| 幼儿园 | 班型系数、岗位、校龄、考核、岗位津贴、骨干津贴、校车补贴 |
| 招生 | 底薪 + 招生业绩提成（业绩数据财务录入+总校确认） |
| 安保 | 岗位工资、轮班补贴、节假日值守 |

- PAY2-1 规则引擎统一化：方案项类型收敛为「固定额 / 档位表 / 数量×单价 / 阶梯分段 / 比例」五种原子规则，所有岗位方案由原子规则组合，避免每岗位写死代码。
- PAY2-2 结算流程复用一阶段：员工确认 → 主管审批 → 财务复核 → 锁定 → 导出；工资单结构（明细行+计算依据）复用。
- PAY2-3 每岗位方案上线前必须通过「平行核算」：系统结果与财务手工表并跑一个月，差异逐条归因清零后才切换。

### 3C OA 审批（OA）

在二阶段审批数据结构上抽出**通用审批引擎**（步骤表驱动、会签/或签、按组织架构找审批人）。

- OA-1 请假：事假、病假、产假、陪产假、婚假、丧假、年假/寒暑假；额度与证明材料要求按学校制度配置；批准结果写入考勤，抵扣异常。
- OA-2 加班：前置申请 → 实际打卡工时复核 → 主管确认；确认后生成加班工时事件供 3B/3D 使用。
- OA-3 补卡：次数上限（默认每月 3 次，学校确认）；超限走特批。
- OA-4 调课审批升级：一阶段调课的行政直批升级为「教师发起 → 教务审批」，审批通过自动执行调课（复用一阶段调课接口与全局冲突校验）。
- OA-5 待办中心统一：与二阶段人事审批同一入口，移动端可审批。

明确不做：自由流程设计器（流程模板由开发配置，不开放学校自助拖拽）。

### 3D 考勤扣款与薪资联动（DED）

- DED-1 扣款规则表：迟到/早退（分钟阶梯）、缺卡、旷工（按日扣 + 纪律处理标记）、空堂（教师未签到课次，一阶段已不计薪，此处补制度性扣款可选项）；**全部金额/公式必须以学校书面确认稿为准录入，系统只做规则执行者**。
- DED-2 扣款先出「预扣清单」：每月结算前生成，员工可见可申诉（走 OA），申诉期 3 天后进入工资。
- DED-3 请假与扣款互斥核算：已批假期覆盖的异常不再扣款。
- DED-4 所有自动扣款在工资单中逐条列示来源（哪天、什么异常、什么规则、多少钱）。

### 3E 津贴评审、报销与全员报表（AWD/EXP/RPT）

- AWD-1 名师津贴：申报 → 评审（评审组会签）→ 公示期 → 按学期发放计划写入工资；学期考核不通过的余额取消规则。
- AWD-2 课题奖励：申报 → 审核 → 公示 → 一次性/分期发放留痕。
- AWD-3 寒暑假工资资格：按学年度出勤与续聘状态自动初筛 + 总校终审，结果驱动假期月工资生成。
- EXP-1 报销：申请（附件）→ 主管 → 财务 → 打款标记；仅做流程与台账，不对接银行。
- RPT-1 全员工资总表：按月全员汇总、分部门小计、同比环比；总校管理员与财务可见。
- RPT-2 人力成本看板：部门月度人力成本趋势、编制内外占比。
- RPT-3 导出：全员工资表、分部门表、银行报盘格式 CSV（格式按学校代发银行确认）。

## 3. 角色变化

- 新增「主管」审批语义：按组织架构 `reportsTo`/部门负责人解析，不新建角色。
- 评审组：名师津贴评审的临时会签组，由总校管理员按学期指定。
- 全部移动端页面（打卡、请假、审批待办）对全员开放，复用现有响应式前端与小程序框架。

## 5. 接口策略

- 考勤/审批/工资接口按批次独立命名空间（`/api/att2/*`、`/api/oa/*`、`/api/pay2/*`），不动一阶段教师链路既有接口。
- 移动打卡接口幂等（客户端重试不产生重复流水），沿用一阶段签到幂等模式。
- 所有列表接口强制分页 + scope 过滤，沿用二阶段权限中间件。

## 6. 非功能需求

### 6.1 性能

- 打卡峰值：全员 1500 人在 7:40-8:10 集中打卡，设计目标 100 req/s 峰值写入（一阶段写合并已验证支撑，SQL 层重新压测）。
- 月度结算批量：全员工资生成 < 5 分钟，后台任务化（复用排课异步任务框架）。

### 6.2 安全与合规

- 定位打卡若启用：仅采集打卡瞬时坐标、明示告知、员工首次使用需在端上确认知情同意；坐标保留 ≤ 12 个月。
- 工资数据分级：他人工资金额仅财务与总校可见；主管审批加班/请假看不到工资。
- 全部审批与扣款可追溯：制度争议时可导出完整证据链（申请、审批、打卡原始记录、规则版本）。

### 6.3 可运维

- 每批次独立 feature flag，可灰度到指定部门试点（建议每批先选 1 个部门跑 2 周）。
- 规则引擎变更走版本化 + 生效日期，禁止直接改当月已结算规则。

## 7. 验收标准（按批次）

- 3A：试点部门连续 2 周打卡流水完整率 ≥ 99%，异常标记与人工核对一致；补卡走流程。
- 3B：每个岗位方案与财务手工表平行核算 1 个月，全员差异金额为 0 或逐条确认归因。
- 3C：四类流程走通并与考勤联动（批假抵扣异常）；审批平均时长看板可见。
- 3D：预扣清单 → 申诉 → 入工资全链路；已批假不重复扣款断言测试。
- 3E：名师津贴完整学期周期演练；全员工资总表与分部门表和银行报盘格式经财务确认。
